# A06: bounded graph and recovery

Owner: **Abhishek**. Workstream: `codex/a06`, based on the approved CP2 baseline.
Scope: C09 orchestration with an explicitly injected, scripted C10 seam. This is
not a real-model experiment or CP3 approval.

## What was built

- `contracts/workflow.py` defines pinned run specifications, budgets, plans,
  typed action proposals, observation assessments, context and turn manifests,
  run state and cancellation requests. Exported JSON schemas mirror runtime models.
- `workflow/runner.py` composes a LangGraph with deterministic preflight,
  investigation, drafting and verification nodes. One `advance` executes one
  controlled turn. The investigator persists its plan before a tool, assesses the
  observation afterward, and links revised plans to their predecessor and trigger.
- `workflow/store.py` stores immutable specifications/states and complete turn
  manifests through the existing application audit kernel. State writes use
  optimistic version checks. State, manifests and audit results commit together.
- A separate LangGraph SQLite database is a rebuildable checkpoint cache. Resume
  verifies the supplied checkpoint reference against the authoritative application
  ledger; an interrupted turn resumes from its exact committed reservations and
  intents. Cache state cannot overwrite newer ledger state.
- `WorkflowStages` and the typed `ToolBinding` registry expose trusted composition
  seams. The model can propose only six named read/check operations with validated
  arguments. It receives no SQL, shell, arbitrary execution or review capabilities.

The state path is `CREATED → PREFLIGHT → INVESTIGATING → DRAFTING → VERIFYING →
AWAITING_REVIEW`. Input/output blocks, failures and cancellation are explicit.
Verification may return to drafting once. Review outcomes are represented in the
contract, but A06 does not fabricate a human approval or implement C13 transitions.

## Bounds and failure behavior

Default limits are eight investigative tool attempts per finding, two query
reformulations, one retry per logical operation and one report repair. Case
actions, model calls, conservative token reservations, preflight/verification
actions and wall time also have explicit configurable ceilings. Mandatory draft
and verification actions are reserved when admitting investigation work.

Each external attempt has an audit intent and a retained structured result.
Known failed attempts may retry once under the same operation ID and a new attempt
ID. Unknown completion stops the run; it never triggers an automatic repeated
call. Repeated identical actions stop as cycles. Out-of-scope actions, invalid
schemas and unsupported resolution claims cannot become accepted findings.
The model may request no-new-evidence abstention or expert escalation; it cannot
declare review rejection, manual closure or supported resolution through a stop
label. Those outcomes require the appropriate trusted handler or assessed state.
Completed observations receive an explicit unknown assessment if execution bounds
prevent model assessment. Cancellation retains the operator's reason.

Reservations and measured usage are separate. Missing provider token/cost metadata
stays unavailable. A per-call usage overrun remains blocked after restart. No
pricing table, monetary ceiling enforcement, provider selection or automatic
fallback is claimed. Synchronous adapters must enforce their own transport
timeouts; elapsed time is checked before dispatch and after return, rather than
claiming the graph can preempt arbitrary injected Python code.
The injected seam's optional normalized usage fields are `total_tokens` and a
finite, nonnegative decimal `cost_usd`. A future gateway must map its actual
provider response explicitly; this does not assume any provider's response shape.

External LangSmith tracing is disabled for graph invocation. Checkpoint
serialization disables pickle fallback and module reconstruction; channels hold
primitive control state. Originals and application audit records remain under the
existing CP2 evidence boundary.

## Reproduction and verification

```sh
uv sync --locked
uv run pytest tests/unit/test_workflow_store.py tests/integration/test_a06_workflow.py tests/integration/test_a06_usage_recovery.py tests/integration/test_a06_control_records.py
uv run scripts/export_schemas.py --check
uv run scripts/verify_a06.py --data-root .recycleguard/a06-reproduction --output tmp/a06-reproduction
```

Use fresh, separate data/output directories for each demo. The script first builds
the CP2 synthetic foundation, then demonstrates weak evidence, a revised plan,
query reformulation and scripted resolution. It exports the specification, final
state, turns, exact scripted exchanges, tool observations and application audit.
The generated summary identifies all scripted decisions and unmeasured behavior.
No test-package import, hidden oracle, real provider or OCR installation is needed.
Dependency installation may require network access.

Tests cover authorization, exact replay, CAS, corruption, transactional rollback,
budgets, adversarial proposals, bounded repairs/retries, cancellation, checkpoint
reconstruction and crashes before/after reservations, external results and turn
commit. Windows and Linux run the same graph tests and demo in CI on Python 3.11
and 3.12. Final verification evidence is recorded in the feature-branch commit/CI.
