## Implemented path

`FoundationService.build` connects:

`audited case intake -> original source capture -> audited extraction -> audited
normalization -> draft profile -> frozen case snapshot + frozen corpus snapshot`.

Every stage has a retained request/result and parent operation reference. Full
observations, coverage and normalized payloads are archived, including anything
not mapped into a usable record. Snapshot membership pins originals, all receipts,
extraction result blobs, manifest/cut-offs, normalization dispositions and exact
profile reference. Corpus membership pins source originals, source classes and
versions, rights-review seeds, page-context provisions and applicability proposals.

These are staged audited operations, not one transaction over the whole pipeline.
Exact request/context replay reuses committed stage results. The crash-window test
first inspects durable state, removes the injected audit failure, then explicitly
resumes the pending operation without duplicate intake. There is no automatic
retry after OUTCOME_UNKNOWN. Each individual catalog publication remains atomic
with its audit result; unreferenced blobs can remain after a failed transaction.

The service returns ServiceResult. A prepared candidate returns PARTIAL with an
UNAPPROVED_PROFILE issue, rather than claiming an approved evidence foundation.
The CLI uses exit code 1 for that non-success outcome and still emits the complete
JSON candidate. Authentication/schema preflight and unavailable storage do not
invent audit events that could not be recorded.

## Integration repairs

1. **Intake:** recursive every-file accounting includes the original manifest,
   nested files, separate duplicate-path receipts, missing files and rejected
   symlinks. Capabilities are checked before archival. Partial dispatcher arguments
   fail clearly. Replay returns the archived complete result. Unknown capture
   times remain unknown. Filenames do not establish payment, allocation, official
   authority or an automatic rights decision.
2. **Acquisition:** success/failure outcomes can be committed through the shared
   coordinator; a failed acquisition has an audited receipt without invented bytes.
   Standalone calls are preparation helpers, not claims of audited persistence.
3. **Extraction:** CSV values preserve decimal strings and leading-zero IDs.
   Root JSON pointers use the empty string. PDF text extraction uses the installed
   parser explicitly; corrupt PDFs fail with an issue instead of trying multiple
   backends or inventing pages. Unsupported scans remain quarantined. No OCR/VLM
   dependency, model choice or heavy inference runtime was added.
4. **Normalization:** required facts no longer default to zero, copper, completed
   transfer or a reporting year. Unknown/invalid observations receive terminal
   quarantine dispositions. Full supplied domain records are mapped and retain
   their complete fields through a discriminated union. Their new provenance
   refers to actual extraction observations. Supplied event/allocation claims stay
   PENDING and validation stays REVIEW_REQUIRED until the later checks establish
   support. Raw observations never grant themselves source authority.
5. **Equivalence/numbers:** complete timestamp value, precision, timezone, lot,
   stage and parties are retained. Same-day partial transfers remain distinct.
   Deduplication requires an external event ID from a server-configured authoritative
   artifact; uncorroborated duplicates or coarse-time collisions stay pending.
   Numeric conversion preserves up to eight source decimal places with precision
   traps; four-place formatting never silently rounds normalized evidence.
6. **Packaging:** uv/pyproject/lock remain authoritative. The duplicate requirements
   file was removed. The existing pdfplumber parser moved from dev-only to runtime
   dependencies without changing its locked version. Existing macOS/Linux
   owner/session checks remain enforced.

## Reproduction and verification

A FoundationRequest uses repository-relative paths (or explicit absolute paths):

```sh
uv sync --locked
uv run recycleguard foundation build /path/to/foundation-request.json
uv run pytest tests/integration/test_a04_foundation.py tests/integration/test_cp1_repairs.py -q
```

Use the `request` object in the candidate packet as the JSON payload and a fresh
RECYCLEGUARD_DATA_ROOT for a new build. Change IDs/expected heads when intentionally
publishing another revision into an existing root. The CLI issues a new context;
programmatic exact replay retains the original context. Fresh builds can differ in
IDs/timestamps and output digests; source hashes and declared behavior are pinned.
No hidden oracle or expected-answer artifact is loaded by the pipeline.
